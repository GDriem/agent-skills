# Adapter: codex

How the neutral skills in `skills/` run in the OpenAI CLI (`codex`). Verified with 0.166.0 on 2026-11-02; what
was tested in this repo is marked **probado**, the rest comes from the docs cited in
[docs/harness-matrix.md](../docs/harness-matrix.md).

## Install

| Scope | Path |
|---|---|
| User | `~/.agents/skills/<name>` → symlink to `skills/<name>` |
| Project | `<repo>/.agents/skills/<name>` (**probado**) |

- **`~/.codex/skills` is still read** (**probado**: with an old `pr-review` there and the new one under
  `.agents/skills`, the session loaded both `SKILL.md` files and mixed their instructions). The docs no longer
  list that path, but 0.166 honors it. `install.sh --check` reports a same-name skill there as a conflict and
  `install.sh --harness codex --retire-conflicts` moves it (and `~/.codex/prompts/<n>.md`) to the backup.
- `~/.codex/prompts` (custom prompts) are deprecated; do not install there.
- `agents/openai.yaml` (display name, short description, default prompt, implicit invocation policy) is
  generated by `install.sh` inside `skills/<n>/agents/`, which git ignores, so there is still one symlink per
  skill. The `-all` skills get `policy.allow_implicit_invocation: false` (**probado**: they disappear from the
  skill list in the model's context, and `$pr-review-all` still injects the skill, from the real path).

## Invocation and arguments

- `$pr-review 401 --dry-run`, `/skills`, or implicitly.
- `$ARGUMENTS` is **not** substituted: the model sees the literal placeholder. The model does receive the text
  after `$pr-review` and reads it as the arguments (**probado**: `hola --dos` arrived verbatim). The neutral
  sentence "the text that follows the skill name" is what makes it work here.

## Capabilities

| Capability in the skill | How it is met here |
|---|---|
| Run shell commands | the shell tool (`zsh -lc` / `bash -lc`) |
| Read files / search files by name | shell (`cat`, `rg --files`, `git ls-files`); there is no separate read tool |
| Write a file (temporary payload, report) | `apply_patch` or a shell heredoc. Inside `workspace-write`, only the workdir, `/tmp` and `$TMPDIR` are writable: set `AGENT_SKILLS_RUNS` under one of them, or add the runs directory with `--add-dir` |
| Ask the user and wait | a question in the reply, then wait for the next turn (interactive). Under `codex exec` nobody answers: the skill follows "No one to ask" |
| Launch a fresh agent with its own context (the `-all` skills) | `multi_agent` (stable, on by default in 0.166). Tools (**probado**): `spawn_agent`, `wait_agent`, `send_message`, `followup_task`, `interrupt_agent`. **Pass `fork_turns: "none"`**: the default `"all"` copies the parent's whole conversation into the child (**probado**: with `"all"` the child knew a word only said to the parent; with `"none"` it did not). `spawn_agent` also takes `model` and `reasoning_effort` |

`spawn_agent` fails under `codex exec --ephemeral` ("no rollout found for thread id"): the child loads the parent
thread from the session store, which `--ephemeral` does not write (**probado**). Do not combine the `-all`
skills with `--ephemeral`.

## Batch skills (`pr-review-all`, `pr-ready-all`)

- **Sibling path.** The session lists every skill with the path of its `SKILL.md`; `realpath` of
  `<dir>/../pr-review/SKILL.md` gives the real file, and the child reads it with the shell (reads are not limited
  by the sandbox) (**probado**).
- **One child per PR**: `spawn_agent` with `task_name` (`review_<n>`), `fork_turns: "none"`, the prompt from
  `batch.md` as `message`, and `model` when `--model` was given (**probado**: the orchestrator passed
  `fork_turns: "none"` on its own, and the children's rollouts record `thread_spawn` with the parent's id and
  `depth: 1`). Keep at most `--parallel` alive; spawn the next when one finishes. A group of `trivial` PRs is one
  child (`review_<n1>_<n2>…`) with the group prompt of `batch.md`.
- **Budget tier** (`trivial` and `small` PRs of `pr-review-all`): `reasoning_effort: "low"`, plus `model` only
  when `--small-model` was given (Codex has no small/large aliases, as in `orchestrate`). `bin/pr-batch` passes
  `-c model_reasoning_effort=low` and `-m <small-model>`. `normal` PRs take `--model` or nothing.
- **Waiting**: `wait_agent` with a long `timeout_ms`. In the first smoke the orchestrator polled with
  `timeout_ms: 10000` and one `sleep`, which cost five extra turns of ~30 k tokens each; `batch.md` now asks for
  the longest wait.
- Works under `codex exec` (**probado** with `$pr-review-all … --dry-run` and `$pr-ready-all … --dry-run`), as
  long as it is not `--ephemeral`. Add the runs directory with `--add-dir` so the orchestrator and the children
  can write there.
- Token counts per thread: each child has its own rollout under `$CODEX_HOME/sessions/…`; the last
  `token_count` event holds the totals. The `turn.completed` event of `--json` only covers the parent.

## `orchestrate`

- **Tiers.** Codex has no small/large model aliases, so the tier moves the effort instead: `small` →
  `reasoning_effort: "low"`, `default` → nothing, `large` → `"high"`. An explicit `effort` in the task wins.
  `model` only when the user gave one (`spawn_agent` `model`; `-m` in `bin/agent-batch`, which also maps the tier
  to `-c model_reasoning_effort=…`).
- **One child per task**: `spawn_agent` with `task_name` (`task_<id>`), `fork_turns: "none"`, the task prompt of
  `contract.md` as `message`. Read tasks of a wave up to `--parallel` alive at once; write tasks one at a time.
  Wait with `wait_agent` and the longest `timeout_ms`, as in the batch skills.
- The orchestrator commits (`--commit`) and runs the checks itself with the shell. In `workspace-write`, the
  children can only write under the workdir, `/tmp`, `$TMPDIR` and `--add-dir` directories: start the session in
  the repository root and add the runs directory with `--add-dir`.
- Not under `codex exec --ephemeral` (children need the session store).
- **Probado** with the same 3-task graph as Claude Code, under `codex exec -s workspace-write --add-dir <runs>`:
  three children (`thread_spawn` in their rollouts), `fork_turns: "none"` passed by the orchestrator on its own,
  the write task started after the reads, and the run line parsed. `--dry-run` launched nothing.
- **`--only`, probado**: `$orchestrate --only t3 --run-dir=<that run> --yes` spawned a single child for t3, took
  t1 from the earlier `summary.json`, left the t1 and t2 lines untouched and rewrote `summary.md`.

## Headless (for `bin/pr-batch` and `bin/agent-batch`)

```bash
AGENT_SKILLS_RUNS="$RUNS" codex exec -C "$WORKDIR" \
  -s workspace-write -c approval_policy=never \
  -c sandbox_workspace_write.network_access=true \
  -o "$WORK/pr-401.codex.txt" \
  '$pr-review owner/repo#401 --auto --run-dir='"$RUN_DIR" < /dev/null
tail -n 1 "$WORK/pr-401.codex.txt"      # the contract line
```

- **Close stdin** (`< /dev/null`). Without it, `codex exec` started from a script waits forever on "Reading
  additional input from stdin…" (**probado**).
- `-o FILE` writes only the final message; `--json` gives JSONL events if the batch wants token counts.
- **Network.** In `workspace-write` the sandbox has no network. A `prefix_rule(pattern=[...], decision="allow")`
  in `~/.codex/rules/*.rules` runs the matching command outside the sandbox, with network (**probado**:
  `gh pr view` allowed by a rule worked, `gh api` with no rule failed with "error connecting to
  api.github.com"). The skills call many `gh` subcommands (`api`, `pr view`, `pr diff`, `pr checks`,
  `search`), so either allow the prefix `["gh"]` or pass `-c sandbox_workspace_write.network_access=true` for
  the run (**probado**, no config file touched). The second is what `bin/pr-batch` uses.
- `bin/pr-batch --harness codex --dry-run <n>` on a real PR after the move to `bin/lib/batch.sh`
  (**probado**): contract line parsed, `posted:false`, `summary.json`/`summary.md` written, exit 0.
- **The shell is a zsh login shell** (**probado**): it sources the user's profile, which puts the real
  directories back in front of `PATH`. A fake `gh` (or any stub) prepended to `PATH` before `codex exec` is
  bypassed by the commands the model runs. To put a stub in front, point `ZDOTDIR` at a directory whose
  `.zprofile` sources the real one and whose `.zlogin` prepends the stub. A fake `HOME` also hides the keychain
  that `gh` reads its token from: pass `GH_TOKEN`.
- `-m <model>` per PR; `-c` overrides any config key for one run.
- `CODEX_HOME=<dir>` isolates a run from the user's skills and memories. A directory with symlinks to
  `~/.codex/{auth.json,config.toml,rules}` and no `skills/` is how the smoke avoided the old port (**probado**).
